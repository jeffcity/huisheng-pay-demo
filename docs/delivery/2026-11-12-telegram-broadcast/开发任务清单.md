# Telegram 机器人群发通知

**开发要做**

1. **租户端：通知中心 → 查单机器人配置**
   - 复用代收、代付查单机器人，两边都支持群发。
   - 各增加「开启群发消息功能」开关和一个「群发指令群 Chat ID」，分别保存，默认关闭；关闭后保留群号。
   - 只有功能已开启、指令来自指定群、发起人实时验证为该群群主或管理员，并引用了通知消息，才允许发送。普通成员、机器人账号、身份查询失败均不发送。
   - 原有查单、绑定等指令保持原规则。

2. **机器人：增加两类群发指令**

   | 指令 | 发给谁 |
   |---|---|
   | `通知商户` | 本租户全部有效且已绑定通知群的商户 |
   | `通知商户=商户1` | 指定一个商户 |
   | `通知商户=商户1，商户2` | 指定多个商户 |
   | `通知通道` | 本租户全部有效且已绑定通知群的具体通道 |
   | `通知通道=通道1` | 指定一个具体通道 |
   | `通知通道=通道1，通道2` | 指定多个具体通道 |

   名称精确匹配，支持中英文逗号。通道不是通道商；「通知商户」不按产品或通道关系缩小范围。

3. **接收群：直接使用已有绑定**
   - 使用商户、代收通道、代付通道已有的通知群列表，后台添加和机器人绑定的数据保持一致，不再维护另一套名单。
   - 一个对象可以有多个接收群；多个对象共用同一个 Chat ID，只发送一次。
   - 只读取当前租户的对象和群。禁用、未绑定的对象不参与发送，并在结果中说明。

4. **消息发送：原通知和统计反馈分开**
   - 商户／通道群收到被引用的原消息，保留文字、图片、图文、视频、文件、格式和链接。不支持的内容明确报错，不改成残缺的纯文字。
   - 发起管理群收到统计反馈：通知类型、范围、目标数量、成功数、失败数、操作人、执行时间及失败原因。
   - 反馈直接从字段开始，不加「群发通知执行完成」等标题。
   - 单个群失败，继续发送其他群；全部失败也要反馈。接口明确确认发送成功才计成功，超时不能直接算成功或盲目重发。
   - 原通知的群发结果和统计反馈自身的发送结果分别记录。

5. **后台日志：复用原页面，保持最小改动**
   - 租户端复用「通知中心 → 发送的消息 → TG 推送记录」。保留原筛选和三列表格，只增加两类群发事件及「群发详情」入口。
   - 同批次一条记录，详情分「推送内容」「反馈内容」，分别显示接收群、时间和发送结果；可查看各接收群的失败原因。
   - 保存批次号、操作人、机器人、原指令、范围及两类消息快照。导出包含推送原文和反馈内容，原有通知按原方式展示。
   - 平台端支持查看有权访问的跨租户群发日志，显示租户名称、编号，并可按租户查询；详情使用相同口径。商户端不增加群发页面。

6. **防重复和并发**
   - 每次群发有独立批次号，多人同时操作不能串消息、串对象。
   - 重复触发不能重复发送。同一原消息分别通知商户和通道，按两个任务处理。
   - 若发生重试，只处理明确失败的目标，不重发已成功的群；本次不自行增加人工重试按钮或指令。

7. **权限一起维护**
   - 同步配置、保存、日志查询、详情、导出的菜单／按钮权限、后端校验和现有角色授权。
   - 租户只能访问本租户记录；平台按授权访问。后台角色权限不能代替机器人每次的指定群和实时管理员校验。

**测试要验**

1. 两个机器人分别检查开关、指定群及管理员身份；任一条件不满足、未引用消息或身份查询异常时，都不发送。
2. 六种指令逐项检查，接收对象和群准确；同群多对象不重复发送，不跨租户，不把具体通道扩大成整家通道商。
3. 检查文字、图文、视频及文件。接收群只有原通知，管理群另收统计反馈；成功、部分成功、全部失败均能核对。
4. 检查重复触发、多人同时操作、超时和重试，不能重复发送或把未知结果计成成功。
5. 检查日志两块内容、群号、时间、结果与导出一致；原通知展示不变，并验证无权限账号和跨租户访问限制。

**开发前还需确认：**同名对象怎么处理、指定名单中部分对象无效时是否整批拒绝、判重时限、统计按对象还是去重后的群计数、超时后的核实方式、相册是否支持，以及平台端日志的具体入口。以上不按 Demo 示例自行定规则。
