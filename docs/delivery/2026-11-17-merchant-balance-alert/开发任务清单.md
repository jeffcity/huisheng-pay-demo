# 商户余额预警

## 开发要做

1. 租户端「商户管理 → 修改商户 → Telegram 通知」增加「代收余额预警」「代付余额预警」两组配置，各自设置开关和金额阈值，各自按对应业务的剩余预付判断。开启时阈值必填，可为0，最多2位小数；需配置商户通知群。关闭后保留阈值。保存沿用商户编辑权限、租户范围和底部谷歌验证码验证。
2. 「通知中心 → 通知配置」增加「商户代收余额不足」「商户代付余额不足」两种消息模板。模板分别维护和启停，每种类型只配置一条，选择代收或代付查单机器人发送。机器人复用查单配置，不新增机器人或复制Token。
3. 这两种模板的「TG群ID」置灰，显示发送至触发商户通知群的说明。后端忽略客户端提交的固定群ID，使用触发商户当前的通知群列表，多群去重后发送。其他消息类型仍可填写固定群ID。
4. 模板支持商户名称、商户编号、触发业务、币种、当前剩余预付、预警阈值、触发时间，并可预览。通知内容注明是代收还是代付，金额来源沿用商户列表对应业务的剩余预付，不使用跑量或总预付。
5. 剩余预付首次达到或低于阈值时通知一次；持续不足不重复通知，高于阈值恢复后再次达到或低于阈值才重新通知。去重状态按租户、商户、业务分别保存，两个业务互不影响。未开启、无有效通知群、模板停用或机器人不可用时不发送，保留失败原因。正式发送沿用通知推送记录和模板快照。
6. 新增字段和模板操作接入现有角色、按钮权限、租户范围、后端校验及审计；不得跨租户引用商户或机器人。此项仅通知，不调整余额、不冻结资金、不自动切停业务。

## 测试要验

- 商户设置：验证代收、代付独立开关和不同阈值，关闭或修改其中一项不影响另一项；分别验证开启、关闭、空阈值、负数、超精度、阈值0、取消、错误验证码、保存回显及切换商户隔离；不改变现有通知群和下分机器人用途。
- 通知配置：两种模板独立配置，两个查单机器人均可选择，群ID置灰且不能通过篡改指定接收群；切回其他消息类型恢复填写和校验；重复配置和未定义模板变量不通过。
- 通知触发：代收和代付分别测试首次跌到阈值、持续不足、恢复、再次跌到阈值；核对真实接收商户群、所选机器人、业务名称、金额、日志与模板快照。
- 权限范围：有权可保存，无权、越租户或配置已变化时不保存或发送，保留原状态。
