# 开发任务清单摘要

## 开发要做

1. 登录安全增加“白名单／黑名单”页签。白名单工具栏仅显示“新增白名单”，黑名单工具栏仅显示“新增黑名单”。
2. 黑名单沿用现有白名单设计，提供IP、启用状态、备注、创建时间筛选，以及新增、编辑、启停、分页、导出、单条和批量删除；操作限定当前租户，沿用现有权限和审计要求。切换页签清空勾选，重置回到第一页，导出当前名单已执行搜索的范围。
3. 新增／编辑使用侧边表单：单个IPv4／IPv6必填，备注选填且最多200字；名单内相同IP及等价IPv6不得重复。同一IP可以分别存在两份名单。普通新增黑名单默认停用，通过开关确认启用；取消或失败不保存。
4. 白名单行内提供“转入黑名单”，黑名单行内提供“转入白名单”。确认后同时移除来源、启用目标并切到目标页签；目标不存在时新增并继承备注，已存在时复用，保留ID、备注、创建时间及其他登录保护。取消、状态冲突或失败时不部分转换，成功记录审计。
5. 启用黑名单优先拒绝当前租户后台新登录，同IP命中白名单或没有启用白名单时仍拒绝。转回白名单、停用或删除黑名单后继续执行其他登录校验；API及已登录会话保持不变。
6. 收窄CNY代收、代付订单表格列宽和单元格留白，短字段及勾选列单独压缩，长内容合理换行。保留全部栏位、完整编号、复制和行操作；小屏可展示更多栏位并保留横向滚动。参考总宽分别约1070px、1134px，不改变订单查询、金额统计及导出规则。

## 测试要验

1. 两个页签的新增按钮归属正确，切换名单不携带勾选；筛选、重置、分页、导出及批量操作范围正确，其他租户数据不可操作。
2. IP格式、重复及等价IPv6、200字备注限制有效；普通新增黑名单为停用，启用后显示“拦截登录”，编辑保留原状态和创建时间。
3. 两个方向的转换均移除来源并启用目标；新目标继承备注，已有目标复用且不重复，ID、备注、创建时间及其他登录保护保留。
4. 编辑、启停、删除及转换取消后数据不变；无权限、来源／目标变化或失败时不部分修改，成功转换可追溯审计。
5. 黑名单优先级正确；转回白名单仍需通过密码、Google验证码等其他校验，API及已登录会话不受影响。
6. 在966px及常用桌面视口检查两张订单表，字段完整、表头对齐、金额和按钮不重叠；编号可完整查看及复制，原有订单操作、查询、统计和导出结果一致。
