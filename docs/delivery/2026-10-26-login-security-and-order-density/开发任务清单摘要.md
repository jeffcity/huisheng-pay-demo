# 开发任务清单摘要

本次范围：租户端登录安全，采用仅白名单准入、临时黑名单到期恢复的规则。

## 开发要做

1. 后台新登录必须精确命中当前租户已启用白名单；未知IP、仅命中停用条目、白名单为空或全部停用均拒绝。已启用手动黑名单及有效临时黑名单优先拦截，之后仍需通过账号、密码和Google验证码验证。
2. 黑名单页提供“自动拉黑设置”侧栏，默认关闭，统计窗口（分钟）、累计失败次数（次）、拉黑时长（分钟）初始未设置；开启前均须填写正整数，密码和Google验证码错误两类均计入当前租户同一来源IP。
3. 自动临时拉黑从原白名单转出，保存原记录及状态、备注、创建时间；到期自动移除对应临时黑名单并恢复原白名单。若期间已有同IP白名单配置，保留当前配置；不自动放行未登记IP，也不取消同IP其他手动黑名单。原白名单资料不可用时保持拒绝并提示核对。
4. 临时黑名单行提供“提前解除”，填写原因并确认后恢复原白名单；与到期恢复共用规则。白名单撤下单独的“封锁中／解除封锁”；临时黑名单不使用普通编辑、启停、删除或转为长期规则的操作。手动黑名单继续独立人工维护。
5. 配置按当前租户保存回显；取消、非法参数、权限失效、配置变化或保存失败保留原状态。样例展示白名单启停、IPv6、黑白重叠、到期／提前解除后恢复，以及黑名单手动启停、IPv6和有效临时拦截；历史过程保留审计。
6. 权限同步（必做）：维护页面菜单、查询、编辑、转换、配置查看／修改、提前解除等按钮权限、接口鉴权及目标角色授权，核对存量运营角色。配置查看、修改和提前解除分别授权，未经授权不可操作。
7. 当前原型覆盖配置、预置临时记录到期／提前解除恢复及样例展示；真实登录失败自动计数、达到阈值转出白名单和后台调度仍需接入联调。API及已有会话保持原规则。

## 测试要验

1. 启用白名单IP可继续认证，停用、未知IP、空名单和全部停用均拒绝；黑名单命中优先拒绝，解除黑名单后仍须满足白名单及其他认证条件。
2. 配置首次关闭、三项参数空白；开启必填正整数，取消不保存，保存回显，查看权限与修改权限独立生效。
3. 临时到期或提前解除后，记录从黑名单退出并回到原白名单，原状态、备注、ID和创建时间保留；现有白名单修改和其他手动黑名单不被覆盖或清除。
4. 提前解除原因必填；取消、无权限、来源／目标变化或原资料不可用时不部分恢复。日志能区分自动到期与人工解除且不包含密码、验证码内容。
5. 白名单没有独立封锁状态或解除入口；临时黑名单只有对应提前解除操作，不能通过通用启停、删除或批量操作绕过恢复。直接打开可以看到有效临时黑名单与已经恢复的白名单样例。
6. 966px及常用桌面视口表单和按钮可达；权限菜单和角色授权能配置新增能力，目标运营角色获授权后可用，未授权入口及接口受控。真实失败计数、触发及后台调度单独验收，不能用预置样例证明已接入。
