# 租户端查单机器人配置

本期将蓝盛现有代收、代付机器人能力迁移至汇盛租户端。租户配置机器人后，在已绑定的指定 TG 群发送蓝盛支持的消息或指令，机器人识别并回复对应信息。

## 开发要做

### 通知中心入口

1. 在租户端「运营中心 → 通知中心」的现有页签后新增「查单机器人配置」。页面展示代收机器人、代付机器人两块配置，分别提供「保存」；底部提供「TG操作员」列表。

### 代收机器人

1. 展示并保存「回调报警机器人」「查单机器人token」「回调群ID」。机器人输入项沿用蓝盛 Token 配置方式。
2. 保存只更新当前租户的代收机器人配置；再次进入页面回填已保存内容，保存失败保留原生效配置与当前输入，并显示失败原因。

### 代付机器人

1. 展示并保存「回调报警机器人」「查单机器人token」「报警群ID」「回调群ID」。
2. 展示并保存「驳回通知开关」「报警开关」「商户预付报警余额」「通道预付报警余额」。开关行为、余额口径、精度及报警触发条件复用蓝盛现有代码。
3. 保存只更新当前租户的代付机器人配置，不影响代收配置；再次进入页面回填已保存内容，保存失败保留原生效配置与当前输入，并显示失败原因。

### TG操作员

1. 在查单机器人配置底部展示TG操作员，列表包含序号、用户名、业务类型、业务权限、系统管理员账号、状态、创建时间和操作；提供TG账号搜索及分页。
2. 提供「新增」「修改」，表单包含带@的TG用户名、状态、业务类型、代收业务、代付业务和系统管理员账号；新增默认启用，修改回填原记录。
3. 用户名、系统管理员账号必填；业务类型至少选择代收或代付一项，可同时选择。未选业务时对应权限选择不可用；两组权限可多选，按所选业务保存。
4. 代收权限沿用蓝盛：绑定商户、绑定通道、下发资金、预付增加、预付扣减、结算、执行对账、启用商户/通道、禁用商户/通道、查单反馈、代收回调、代收回调确认。代付权限沿用蓝盛：绑定商户、绑定通道、查单反馈、代付预付增加、代付预付扣减、代付回调、代付回调确认。真实权限编码从原源码迁移。
5. 保存后更新对应记录；取消或关闭不保存。列表支持启用、停用和删除；删除先确认目标，取消保留原记录，确定仅删除目标操作员。
6. 操作员、关联的系统管理员账号及权限按当前租户隔离；开发迁移蓝盛账号关联、权限保存与机器人指令鉴权，并适配汇盛租户范围。

### 指定群消息与回复

1. 从蓝盛现有代码迁移机器人接收群消息、识别特定消息或指令、查询数据及回复信息的完整链路，不只迁移前端表单。
2. 复用蓝盛现有指令文本、参数解析、回复格式、群绑定、操作员校验及异常处理；从源码核对实际支持范围，不另行设计一套指令。
3. 沿用蓝盛已有查单群绑定入口及绑定关系；回调群、报警群继续按原职责使用，不直接当作查单授权群。若原绑定入口尚未迁入汇盛，开发列明具体入口与必要改动供产品确认。
4. 将机器人配置、TG 群绑定、可查询订单和回复内容限定在当前租户；其他租户的 Token、群配置或订单不得被读取、修改或回复。
5. 在已绑定且通过蓝盛原有校验的指定群收到有效指令后，回复对应当前租户信息；未绑定群和未通过校验的消息不执行查询，并沿用蓝盛既有拒绝或忽略方式。
6. 配置校验、保存接口、机器人加载与生效方式、回调报警、驳回通知及余额报警一并从蓝盛复用，适配汇盛租户范围；失败反馈及日志不得暴露完整 Token。

## 测试要验

### 通知中心与配置保存

1. 打开通知中心，三个页签可独立切换，「查单机器人配置」展示两块表单和底部TG操作员列表。
2. 修改并保存代收配置，重新进入仍显示该配置；代付配置保持原值。修改并保存代付配置，代收保持原值。
3. 修改代付两项开关与预付报警余额，保存和回填正确；字段校验、精度与蓝盛一致，保存失败时原生效配置不变。

### TG操作员

1. 按TG账号搜索及切换分页，结果、数量、序号与当前列表一致；无匹配时显示空态。
2. 新增默认启用；用户名、系统管理员账号为空或未选业务类型时不能保存；带@的账号按蓝盛规则校验。
3. 同时选择代收、代付，分别选择多项权限并保存，列表与修改弹窗正确回填；未选业务不能配置对应权限。
4. 修改后只更新目标记录；取消或关闭不保存当前输入，创建时间保持原值。
5. 启停状态回显正确；删除确认展示目标账号，取消不删除，确认仅删除目标，最后一页记录删除后分页仍有效。
6. 不同租户的操作员、关联账号与权限互不串用；机器人对停用操作员及未授权业务沿用蓝盛拒绝或忽略方式。

### 群消息与回复

1. 分别在代收、代付已绑定群发送蓝盛现有有效查询指令，机器人回复当前租户对应数据，参数解析及正文格式与蓝盛一致。
2. 在未绑定群、其他租户群或未通过操作员校验时，无法获得当前租户查询信息；查不存在的订单和不支持的消息按蓝盛原有方式处理。
3. 对比蓝盛代收、代付回调报警、驳回通知开关、报警开关及两项余额报警的正反向行为，汇盛结果与原逻辑一致。
4. 使用两个租户分别配置并查询，Token、绑定群、保存结果及回复数据互不串用；TG失败时保留既有业务结果并提供可追踪的失败信息。
