# 产品决策记录

## 2026-11-02 平台全局订单时间与表格密度

触发问题：用户要求平台全局订单查询与租户端一样展示三类时间，明确使用创建、支付、回调名称；同时指出各列过宽，需要压紧布局。

最终决定：列表同一栏按创建、支付、回调三行带标签展示，无值显示“—”。三类时间独立取值，不将更新时间、状态变更时间或主动查单时间当作支付、回调时间。普通订单提供明确虚拟时间样例；退款只展示已有事实能明确提供的时间。详情与导出同步三类时间，详情继续保留更新时间。

布局：表格采用固定列宽、最小宽度1080像素，表头和内容减少留白；订单编号和长摘要自动换行，摘要完整保留。宽屏显示全部列，小屏只在表格区域横向滚动。筛选区在较窄容器内换为三列、更小尺寸依次两列和单列，查询和重置保持可达。样式仅作用于全局订单页。

决定原因：缩短横向滚动距离，清楚区分订单各阶段时间，保留已有业务内容、权限和只读边界。

影响文件：本地统一Demo/public/legacy/sources/orders.html；test/platform-order-times.test.mjs；src/legacy/sources.json。
