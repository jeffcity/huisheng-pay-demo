# 商户端「手动下单」增加支付宝支付类型

**改动页面：商户端 → 订单管理 → 手动下单。**

## 开发要做

1. **保留通道选择，新增支付类型。**
   - 「通道」选择当前商户可用的具体通道，展示通道名称和编码。
   - 旁边增加「支付类型」：银行卡、支付宝，默认银行卡。两项分开选择，不能互相覆盖。

2. **选支付宝后，表格按这个顺序显示。**
   - 序号、请求金额（元）、银行名称、支行名称、支付宝账号、支付宝姓名、操作。
   - 银行名称、支行名称都自动填“支付宝”，不可修改；每新增一笔也一样。
   - 商户只需填写金额、支付宝账号和姓名。银行卡模式保留原有字段和处理方式。

3. **沿用现有下单接口。**
   - 银行名称、支行名称继续使用现有字段，并提交固定值“支付宝”。只读字段也必须提交，不能因为不可编辑而漏传。
   - 支付宝账号、姓名、金额使用现有对应字段；不新增接口字段，不改现有签名及金额单位。

4. **保留原有录入和验证。**
   - 支持新增、删除，至少一笔，最多50笔；切换支付类型保留各自未提交的内容，只校验当前类型。
   - 通道、支付类型、金额、账号、姓名必填；金额大于0、最多两位小数。
   - 保留谷歌验证码和原有下单校验；银行、支行固定值不需要商户手填。

5. **权限一起维护。**
   - 沿用手动下单菜单和下单按钮权限；核对后端权限校验、现有角色授权及商户／租户范围。
   - 新增或拆分权限时，同步维护权限菜单，避免运营看到按钮却无权操作。

## 测试要验

- 银行卡原流程可用；支付宝列顺序正确，银行和支行始终是“支付宝”、不可编辑，提交数据中两项都存在。
- 新增多笔、删除、切换类型后，通道选择、各类型草稿和固定值正确；50笔上限有效。
- 必填、金额精度、验证码及无权限账号拦截正常；不能使用其他商户或租户的通道。
