# 账户管理｜开发补充说明

## 名称对应

| 界面用词 | 业务含义 |
|---|---|
| 新增“登录账号” | 开发新增表单的“用户名称”，用于登录，不是昵称 |
| 新增“姓名”／编辑“暱称”／列表“姓名” | 同一项展示名称资料，对应开发页“用户昵称”，不拆成多个字段 |
| 编辑“启用”／列表“正常” | 同一个可用账号状态 |
| 编辑“禁用”／列表“停用” | 同一个禁用状态 |
| 角色“停用” | 角色定义状态，区别于账号停用；隐藏角色标签不删除账号或绑定 |
| 下线 | 当前会话失效，允许账号在正常状态下重新登录，区别于账号禁用 |

## 保存与隐藏字段

- 新增只填写四项；状态默认正常。创建时不要恢复已移除资料的必填规则，不自动分配部门或附加角色。
- 编辑登录账号只读；只更新暱称、角色、状态与备注，保留隐藏组织／联系资料和原数据范围。
- 原停用角色可以保留或移除，不能新增停用角色绑定；保存前复验角色可用性及操作权限。
- 普通编辑不触发重置密码或2FA；密码不从账号资料中回填，不记录明文。
- 前端红星与服务端必填规则一致；备注为空代表允许清空，不代表缺少操作原因。

## 状态与会话

- 本次只有正常／停用，状态维护沿用编辑表单，不建设独立锁定／解锁。
- 禁用成功后旧会话失效，重复提交不能重复执行；启用不恢复旧会话。
- 角色编辑继续受既有授权范围与管理员保护约束，不因表单精简扩大权限。
- Demo中旧锁定样例已归为停用。这是演示样例同步，不是对真实开发数据执行迁移；如服务端另有自动安全锁规则，先核实现有语义，不由本稿合并其内部安全机制。

## 补单配置

- 复用已有按账号配置CNY三项额度的能力，调整列表回显、入口、顺序、标签和弹窗展示。
- 列表摘要必须以账号身份对应数据，搜索、排序、翻页或保存后不能按错误行回填。
- 次数非负整数、金额非负且最多两位小数，单次不超过每日；既有数值上限由原服务规则执行。
- 界面里的“每日”是额度配置，不是剩余额度；保存不得清空已用量。
- 零值是否禁补、计数周期及每日重置由现有补单规则控制。本次查看只确认三项配置界面，没有验证实际额度执行，联调需核对原规则，不照搬Demo计数逻辑或另建额度引擎。

## 既有安全动作

- 重置2FA已有原因、字数计数、Google验证码及确认流程，按原规则回归；不增加一套演示验证码或旁路认证。
- 下线的会话执行能力沿用现有系统；本次明确原因确认交互。校验失败、取消或对象已变化时不执行，不把账号状态设为停用。
- 无权限或受保护目标不可写入；拒绝不能仅依赖前端隐藏入口。

## Demo使用边界

- 唯一Demo源码：`surfaces/tenant/public/legacy/sources/system.html`，入口租户端→系统管理→账户管理。
- 当前Demo仍保留重置密码、最近登录时间、导出账号视图等演示能力；这不等于这些能力属于本期开发。
- 当前Demo的额外2FA筛选与独立启停行按钮不扩展本期清单；开发沿用已有搜索、筛选、分页及编辑状态入口。
- 本地模拟不能证明真实密码、Google认证、会话失效、权限与补单执行已接入；验收需要服务端及受控账号验证。
