# 租户端「已授权通道商—代付」优化

## 开发要做

1. **分成“已使用／未使用”两组，默认显示已使用。** 每组显示数量。租户已经用这家通道商创建过代付通道，就算已使用；通道关闭、没有跑量也算。创建第一条通道后归入已使用，删除最后一条后归回未使用。

2. **查询和批量操作跟随当前分组。** 名称／编号只查当前组；切组清空关键词和勾选，回到第一页。汇总、导出和手动结算按当前组的查询结果处理；有勾选时只结算勾选对象，确认时列出实际通道商。

3. **余额从代付通道加总。** 每家通道商余额＝当前租户在这家通道商下所有 CNY 代付通道的余额之和，关闭的通道也计入。已删除通道、代收通道和其他租户不计入。上方总余额、列表、导出和资金弹窗保持一致。

4. **通道商余额调额必须先选通道。** 下拉框只显示当前租户、这家通道商下的 CNY 代付通道，展示名称、编码和余额，不默认选中。沿用现有调额校验；提交成功只调整所选通道，再重新加总通道商余额。没有可选通道时不能提交。

5. **把列表排紧凑。** 缩小列宽、行高和上方留白，刷新、导出放在查询旁。保留全部字段、完整金额和操作；小屏只让表格区域横向滚动。

6. **同步权限和操作记录。** 检查菜单、查询、导出、调额、结算和自动结算设置的按钮权限、后端校验及现有角色授权。操作只能处理有权限的本租户数据；调额记录能查到具体通道、操作人及调整前后金额。

7. **每家代付通道商可开启自动结算。** 列表增加“自动结算”列，每家一个开关及开启／关闭文字，默认关闭；开启、关闭均需确认。开启后，每天凌晨 **00:00（UTC+8）** 按现有手动结算规则执行，关闭后不再自动执行。自动任务不受页面搜索、分组或分页影响。结算结果按「通知中心 → 通知配置 → 代付通道商结算通知」已启用的机器人和群发送。同一批次多家通道商汇总通知，包含执行时间、各家成功／失败／待确认结果和金额信息；失败时说明原因。保留执行记录，同一天不能重复结算；TG 通知失败只重试通知，不能因此再结算一次。

## 测试要验

1. 授权 20 家、只创建了其中 2 家的代付通道时，显示已使用 2 家、未使用 18 家。关闭通道不换组；创建第一条、删除最后一条后分组正确变化。

2. 切组后没有残留勾选或关键词。搜索、汇总、导出及结算对象一致，不带入另一组或未命中的通道商。

3. 同一通道商有两条通道，余额分别为 633,800 和 418,000，通道商显示 1,051,800；关闭其中一条仍计入，修改或删除后同步重算。

4. 选择余额为 418,000 的通道减少 10,000，通道余额变成 408,000，通道商总余额也减少 10,000；其他通道不变。从通道管理调额后，通道商汇总同样更新。

5. 未选通道、余额不足、金额格式错误或验证码错误时不调额；取消、重复提交也不能多扣或多加。没有通道时提交不可用。

6. 小屏能看到更多数据，金额和操作不被截断；有权限账号能正常使用，无权限账号不能操作，也不能通过接口处理其他租户的数据。

7. 自动结算默认关闭，列表能直接看到开关状态。开启、关闭均需确认，取消不改变设置，切页后状态保留。开启后每天00:00（UTC+8）按手动结算规则执行，并按通知中心已启用的结算通知配置汇总发送；关闭的通道商不执行。搜索、分组或分页不影响任务。重复触发不能重复调整金额；结算失败有原因记录，TG发送失败只重试通知。无权限账号不能修改设置。
